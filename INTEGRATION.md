# Group assignment integration

Instructions for adding the skill-cluster group assignment to this app. The two model files are finished. Do not edit them. Adapt the app to their function signatures.

## 1. What these two files do

`cluster_model.py` stores the three k-means centroids for the skill ratings and `predict_cluster` returns the label of the nearest centroid. `assignment_rules.py` calls `predict_cluster` for each student, orders clusters from most students to fewest, sorts each cluster by `id`, and deals that combined list to groups 1 through `n_groups` without restarting the count between clusters. Neither file reads the database: `assign_groups` takes an in-memory list and returns each student's `id`, `cluster`, and `group`.

## 2. Files to copy

Copy these two files into a `model/` directory next to `app.py`:

| File | Destination |
| --- | --- |
| `cluster_model.py` | `model/cluster_model.py` |
| `assignment_rules.py` | `model/assignment_rules.py` |

Leave both files unchanged. Do not copy `fit_clusters.py`, `class_dataset.csv`, or `elbow.png`. The running app does not read that CSV.

## 3. The two functions

`predict_cluster(skills)` takes one sequence of four numbers, in this order: `skill_programming`, `skill_data_stats`, `skill_frontend_design`, `skill_business_pitch`. It returns an integer cluster label, `0`, `1`, or `2`.

```python
predict_cluster((4, 3, 5, 3))  # 2
```

`assign_groups(students, n_groups=8)` takes the whole class and how many groups to make. Each student is a dict with `id` and the four skill ratings under those column names. It returns a list of dicts in the same order as `students`. Each dict has `id`, `cluster`, and `group`. Group numbers start at 1.

```python
assign_groups([
    {"id": "a", "skill_programming": 1, "skill_data_stats": 1, "skill_frontend_design": 2, "skill_business_pitch": 4},
    {"id": "b", "skill_programming": 5, "skill_data_stats": 5, "skill_frontend_design": 5, "skill_business_pitch": 5},
])
# [
#   {"id": "a", "cluster": 0, "group": 1},
#   {"id": "b", "cluster": 2, "group": 2},
# ]
```

`assignment_rules.py` imports `predict_cluster` with `from cluster_model import predict_cluster`. Put `model/` on `sys.path` before importing `assignment_rules`. Do not add an `__init__.py` and import the files as a package: that import would then fail.

## 4. Where the data comes from

The centroids were fit on `class_dataset.csv`. The app never opens that file. `deploy.py` loads the CSV into Postgres, and `app.py` reads Postgres through `DATABASE_URL`. Build each student dict from a query, then call `assign_groups`.

The model inputs are `id` and the four skill ratings. Map them as follows. Use `netid` as the student `id`.

| Model input | Table | Column | How it differs from the CSV |
| --- | --- | --- | --- |
| `id` | `students` | `netid` | Same value as the CSV column `netid`. `students.student_id` is a new integer identity primary key generated by Postgres. It is not the model's `id`. Pass `netid`, because `assign_groups` sorts each cluster by `id` and an integer key would deal students into different groups. |
| `skill_programming` | `students` | `skill_programming` | Same name and the same 1–5 ratings. The CSV stores them as text; the column is `INTEGER NOT NULL` with a check that the value is between 1 and 5. `deploy.py` inserts them with `int()`. Pass that integer through. The fit did not scale the ratings. |
| `skill_data_stats` | `students` | `skill_data_stats` | Same as `skill_programming`. |
| `skill_frontend_design` | `students` | `skill_frontend_design` | Same as `skill_programming`. |
| `skill_business_pitch` | `students` | `skill_business_pitch` | Same as `skill_programming`. |

`assign_groups` reads those five fields by name. There is no `cluster` column to select. The model CSV has a `cluster` column written after the fit; `schema.sql` does not, and `deploy.py` does not insert one. `predict_cluster` computes the label from the four ratings.

`students.name` is not a model input. Keep it beside the call and use it only when building `members`. The return value has `id`, `cluster`, and `group`, so match rows back by `id` (`netid`).

`school_year`, `intro_programming`, `working_style`, `interests`, `semester_goal`, and `submitted_at` stay on `students` and are not inputs. `tools` and `availability` from the CSV are the `tools`, `student_tools`, `availability`, and `student_availability` tables. The model does not use them.

Query:

```sql
SELECT netid, name, skill_programming, skill_data_stats,
       skill_frontend_design, skill_business_pitch
FROM students
```

Student dict passed to `assign_groups`:

```python
{
    "id": netid,
    "skill_programming": skill_programming,
    "skill_data_stats": skill_data_stats,
    "skill_frontend_design": skill_frontend_design,
    "skill_business_pitch": skill_business_pitch,
}
```

## 5. Backend

Add `GET /api/groups` in `app.py`, next to `GET /api/class`. Read every student with the query in section 4, using the same `psycopg2.connect(os.environ["DATABASE_URL"], connect_timeout=30)` pattern as `query_class`. Call `assign_groups` with `n_groups=8`. On a database error, respond the way `/api/class` does: `{"error": "Could not load class data"}` with status 500.

Return one JSON object:

| Field | Contents |
| --- | --- |
| `n_groups` | `8` |
| `groups` | One object per group, groups 1 through 8. `group` is the group number. `members` is a list of `students.name` strings for the students in that group. `cluster_counts` maps each cluster label that appears in the class (`"0"`, `"1"`, `"2"`) to how many of that group's members are in it, including zeroes. |
| `clusters` | One object per cluster that appears, sorted by cluster number. `cluster` is the label. `students` is how many students are in it. `centroid` is the four floats in `cluster_model.CENTROIDS` for that label, in skill-column order. Use those stored numbers. |
| `groups_missing_a_cluster` | How many groups have a count of 0 for at least one cluster that appears in the class. This is the same rule as the direct run of `assignment_rules.py`. |

Do not return any one person's cluster. `members` is names only: no `netid`, no `student_id`, and no `cluster` on a person. The `clusters` array has counts and centroids, not names.

## 7. Packaging

The image is built from `Dockerfile`. It copies `requirements.txt`, `app.py`, `templates/`, and `static/` into `/app`. It does not copy `model/`. Add this next to the other `COPY` lines:

```dockerfile
COPY model ./model
```

No new packages are required. `cluster_model.py` and `assignment_rules.py` use the standard library, and `requirements.txt` already has Flask, gunicorn, and psycopg2. Do not add scikit-learn or pandas. `.dockerignore` does not exclude these `.py` files; leave it that way. It does exclude `class_dataset.csv`, which the app should not need at runtime.

Gunicorn runs `app:app` with working directory `/app`. Copying the directory into the image does not make `import cluster_model` succeed. The `sys.path` change in section 3 has to be in `app.py`, which is already copied.

## 8. Test

Start the app locally with `DATABASE_URL` set and `deploy.py` already loaded, then request the new route:

```bash
curl -s http://127.0.0.1:5050/api/groups
```

`python app.py` serves on `127.0.0.1:5050`. With the same 34 students as the CSV this model was fit on, expect `n_groups` of 8, group sizes 5, 5, 4, 4, 4, 4, 4, 4 for groups 1 through 8, and `groups_missing_a_cluster` of 0. Cluster counts for those groups are in the table in section 6.
